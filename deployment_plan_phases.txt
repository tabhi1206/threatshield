   - Confirmed runtimes: Python FastAPI (backend), Node/Vite + React (dashboard), Chrome Extension (MV3)
   - Identified issues: default JWT secret in `.env`, SQLite in production, missing background script path in extension manifest, no Dockerfile, no CI/CD.

2) Security & Configuration
   - Rotate secrets: generate a strong `JWT_SECRET_KEY` and store in Render secrets.
   - Move sensitive values out of repo; add `.env.example` and ensure `.env` is in `.gitignore`.
   - Tighten CORS to allowed origins only; remove permissive regex in production.
   - Harden CSP: replace permissive `default-src * 'unsafe-inline' 'unsafe-eval'` with minimal allowed sources.

3) Replace/Prepare Production DB
   - Replace SQLite with managed Postgres (Render Postgres) or other managed DB.
   - Add SQLAlchemy DB URL support via `DATABASE_URL` env var (already present) and prepare Alembic for migrations.
   - Export current data if needed and create migration scripts.

4) Tests & Static Checks
   - Add unit/integration tests for core services (threat analyzer, routes), and linting (flake8/ruff).
   - Add `pytest` and CI test job skeleton.

5) Local dev hygiene
   - Add `requirements.txt` pinning (already present) and optionally `pyproject.toml` for reproducible installs.

Phase 2 — Containerize & Deploy Backend and Dashboard (Render)

1) Containerization (recommended)
   - Create `Dockerfile` for backend using Python slim image and production start command.
     Example start command: `gunicorn -k uvicorn.workers.UvicornWorker app:app --bind 0.0.0.0:$PORT --workers 2`
   - Optional: create `Dockerfile` for dashboard (or use Render Static Site).

2) Render setup — Backend
   - Create a Git repo (if not already) and push code to GitHub.
   - On Render, create a new Web Service (or Docker Service) pointing to the backend repo.
   - Set build command (if not using Docker): `pip install -r backend/requirements.txt` and start command using `gunicorn` or `uvicorn` referencing `$PORT`.
   - Add managed Postgres on Render and set `DATABASE_URL` secret in the service settings.
   - Add required secrets: `JWT_SECRET_KEY`, `ALGORITHM`, `ACCESS_TOKEN_EXPIRE_MINUTES`, etc.
   - Configure health check to `GET /api/v1/health`.
   - Configure automatic deploys from the main branch and set up a PR preview service (optional).

3) Render setup — Dashboard
   - Use Render Static Site or Web Service:
     - If Static Site: set repo path to `dashboard/`, Build command: `npm install && npm run build`, Publish directory: `dist`.
     - If Web Service: containerize and use `serve` or a small Node server to serve the built files.
   - Ensure dashboard calls backend via the public API URL (HTTPS). Update `dashboard/src/services/api.js` to use env-provided API base URL at build time.
   - Set CORS allowed origin to the dashboard domain in Render's settings/environment.

4) Domain, TLS, and monitoring
   - Add custom domains in Render, enable TLS (automatic), configure DNS records.
   - Add basic logging / health alerts (Render provides logs and metrics).

Phase 3 — Package & Publish Chrome Extension

1) Fix & Prepare Extension Code
   - Fix missing background script referenced in `extension/manifest.json` (manifest points to `background/background.js` which is absent).
   - Update extension to call the deployed backend domain (use HTTPS) and not `localhost`.
   - Audit `content_security_policy` and ensure no inline script usage or unsafe-eval in extension pages.
   - Build a production-ready popup (minify assets) and ensure all icons exist.

2) Package & ZIP
   - Create a `build-extension` script that copies `extension/` into a temporary folder, runs any bundling (if using ES modules), and zips the final directory.
   - Validate `manifest.json` and test by loading the unpacked extension in Chrome (Developer mode) against the deployed API endpoints.

3) Chrome Web Store Publishing
   - Create Developer account on Chrome Web Store (one-time fee required).
   - Prepare metadata: store listing description, privacy policy URL, screenshots (at least one 1280x800), and icons.
   - Upload the ZIP to the developer dashboard and submit for review.
   - Optionally automate publishing via Chrome Web Store API (generate OAuth tokens and configure CI job to upload on tag changes).

4) Post-publish
   - Monitor extension errors and user reports. Add a versioned changelog and update the dashboard/website.
